# v0.20.50 release notes

English | [简体中文](v0.20.50_ZH.md)

Release date: 2026-10-19. Release type: formal GitHub release, not a prerelease. The Chinese EDA marketplace package has been resubmitted and is under review; the publicly listed version remains v0.10.143. Marketplace approval and listing of v0.20.50 are not confirmed.

## Scope

v0.20.50 packages Chinese EDA menu labels and documentation on the v0.20.49 core. It adds no core write operations. These notes summarize fixes and established limits from v0.20.11 through v0.20.49. Historical operation demonstrations retain their original dates and versions and are not v0.20.50 host acceptance records.

## Changes and operating boundaries

- Parameter and result handling adds invalid-parameter preflight, SDK failure handling, and readback after writes. An uncertain write is reported as partial, dependent operations stop, and the extension does not retry automatically or treat an empty result as success.
- `routeTrack` and SES segment inputs are checked before writing. Any segment shorter than 1 mil is rejected as a plugin policy; this is not an SDK minimum-length limit.
- Online `.epro2` import can derive the project name from the root `project2.json` `title` and pass through `description`, preserving whitespace and line breaks. Schematic-page copying remains supported; if the SDK does not provide an acceptable new UUID, the operation reports the failure evidence and does not retry. This does not change offline import or other formats.
- `modifyPour` requests that change the pour net or name are rejected before writing. Automatic autorouter SES reinjection is disabled; external routing output requires a separate, explicit import flow.
- On EDA 4.1.78, 14 commands requiring EDA 4.2 are disabled and rejected at the version check. Positive execution and persistence on EDA 4.2 have not been accepted. Copper rules and pad heat-welding settings remain read-only diagnostics; unknown units or rule selection are not inferred.
- `pcb.connectComponentPadDirect` is temporarily disabled because configuration could not be reliably read back on the tested host. The compatibility entry point rejects calls before accessing the project or SDK. This does not establish that every version's setter fails, and does not resolve the separate issue of small copper areas failing to connect to pads.

These safeguards and scoped checks do not mean that all underlying issues, geometry, copper-fill results, or persistence behavior have been fixed. Copper contact and save/reopen behavior still require separate checks.

## Verification status

TypeScript checking, the production build, and 31 existing simulated regression suites passed. Runtime verification found no difference from the marketplace-candidate program after removing build-path markers; manifest fields matched. The package has not been reinstalled in EDA for host verification. EDA 4.2 positive behavior has not been verified.
