Refresh `/connections` and verify the window identity before every request. `getContext` checks the project and document before and after forwarding, and the independent plugin also checks the same target. It does not switch pages automatically. Success proves only that identity was read for this request; it does not prove that the schematic and PCB are paired.

Requests use the existing proxy. Proxy source classifies `module.getCopyOperation`, `module.getRestoreOperation`, and `module.getPlacementOperation` as read-only queries; an already-running old proxy may not have loaded that change, so verify it. Other commands use the default ordered queue and unknown-write protection. The independent plugin does not create a second WebSocket. Do not clear protection solely to query a record, and do not call the public message bus directly to bypass the normal command path.

If the plugin is not installed, the RPC call fails, protocol or plugin identity does not match, or data is incomplete, report an explicit failure. For writes, still verify the actual target. The public RPC protocol is 1 and the topic is `module-reuse:rpc:v1`. Treat version as diagnostic information; do not reject responses based on a particular patch version.

Status queries report actual capabilities; do not require exactly 11 items or every command. `nativeCapabilities` may be omitted. If present, verify its actual Boolean values; do not require exactly two entries. Do not add a handshake, preflight call, or capability cache.

`capturePair` switches to and reads the source documents but does not modify design content. Captures are stored in the independent plugin's configuration and are not portable module files.

The target project for `probeNativeCopy` must differ from the source. `documentType` accepts only `schematic` or `pcb`; for PCB, do not pass a target-board name. Each command calls the native copy operation exactly once. A schematic copy adds a page; a PCB copy adds a free PCB. It does not automatically delete target placeholder documents.

The same `operationId` with the same parameters returns the existing status; changed parameters are rejected. Before writing, persist and read back the operation record. After the SDK call, any exception or identity/content-check failure stops the process; retain the copy UUID and unknown result and do not retry. Use `getCopyOperation` to inspect the record. Do not bypass an unknown state by changing `operationId`.

## Restore a Native File

First save the native file, then reread its contents from disk and pass them as `base64`. `fileName` accepts only a `.epro` or `.epro2` filename without a path. The independent plugin always uses `JLCEDA Pro` and `Existing Project`; the AI cannot choose an arbitrary file type or import mode.

`targetProjectUuid` must be the currently verified isolated target project. Before writing, persist the operation and file-content digest, recheck the target, then call import exactly once. The same `operationId` and input only read the existing result; the same ID with a different file or target is rejected. An empty SDK result, target mismatch, read-back failure, or storage failure stops the process. Do not retry with a different ID.

`fileImported` / `metadataVerified:true` means only that the SDK returned the target UUID and the project tree showed a checkable change. `contentVerified:false` explicitly means that all design content was not checked. A new board does not mean it has been merged into the target's existing schematic or PCB. Separately verify complete resources, independence of two instances, the CBB template relationship, and save-close-reopen.

Query `module.getRestoreOperation` for an existing record. An unknown state does not become successful through a query or restart. The standalone file must include the required resources. Do not temporarily restore missing content from the source project or cloud library and then call it an independent restoration.

## Read-Only Export of a Specified Template

`module.exportTemplateFile` accepts only the six required parameters in the table. `fileName` must be a `.epro2` filename without a path. Before and after export, verify the current project, that the selected SCH and PCB belong to the same board, and their correspondence to the CBB library entry. If anything changes, reject the result and do not return a usable file.

The independent plugin calls the official CBB file export and explicitly specifies both template UUIDs. It does not switch projects, modify a library template, import, or place anything. The response includes `exported:true`, filename, size, type, and base64. `contentVerified:false` and `templateBindingVerified:false` mean that template content and reuse association still require checking.

Save the returned file to disk, inspect the template and resources actually selected by the host, and separately verify restoration from the file and references from the cloud library. Successful export does not mean the library template was modified. Proxy source classifies this command as read-only; an old running proxy may not have loaded the change. Do not restart and discard unknown-write protection for this query.
