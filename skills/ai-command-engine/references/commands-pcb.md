# PCB Workflow

Before writing, read [PCB Operating Requirements](PCB操作要求.md) and plan component placement, routing, and copper pours according to its requirements.

First verify the window, project, PCB document, and units using [Connections and Environment](setup.md). Common entry points are [Frequently Used PCB Commands](commands-pcb-high.md) and [Less Frequently Used PCB Commands](commands-pcb-low.md). Check parameters and return fields in `/help?cmd=<command name>` for the confirmed version of the selected window; `/help` uses the window currently selected by the proxy.

## Receive the Design and Inspect the Current State

The user initiates and confirms schematic-to-PCB updates in the EDA interface. AI must not call `pcb.importChanges` or the official import interface. Before and after an update, use `pcb.listComponents`, `getComponentPads`, and `listNets` to check component identities, footprint associations, per-pad nets, and non-target objects. A successful plugin receipt does not replace saving, reopening, or a whole-board check.

## Board Outline, Layers, and Placement

- Public coordinates for `pcb.drawOutline` use the lower-left as the origin and mil as the unit. Before repeating an outline, inspect the actual primitive type and ID; do not assume it is a Region.
- Check layer count and stackup separately. `setCopperLayers.count` accepts only even numbers from 2 to 32. Read the complete configuration with `getStackingConfig` and read it back after `applyStackingConfig`. Setting the default stackup does not mean it has been applied to the current PCB. Reactivate the PCB after changing custom layers. Do not guess unknown layer names or numbers.
- `getCurrentLayer`, the physical-stackup configuration commands, and the real-time DRC toggles were confirmed unsupported on EDA 4.1.78. They require EDA 4.2 or later; 4.2 has not yet passed host acceptance. See [PCB Less Frequently Used Commands](commands-pcb-low.md#eda-version-restrictions) for each command name.
- After `pcb.moveComponent`, use `checkPlacement` to check clearance. It uses pad bounding boxes and cannot replace checks of component bodies, silkscreen, or mechanical dimensions. Do not report all placement as passing if `complete:false` or objects were skipped.
- Use `pcb.groupBySchematicRegions` when explicitly asked to organize by schematic functional area. First inspect `dryRun`, board-outline capacity, and the sources of dimensions; then execute and read back. It is not the entry point for moving an ordinary single component.

## Fanout, Routing, and Autorouting

After positioning fine-pitch components, use `pcb.getFanoutPlan` to check the target, layer, dimensions, and `executable`, then pass the complete `data` as `params.plan` to `pcb.fanout`. See [PCB Geometry Commands](commands-pcb-special.md) for geometry boundaries.

For manual routing, use `pcb.routeTrack`; change layers with `pcb.placeVia`. First confirm that the net exists, then choose track width and via size according to current, rules, and board layers. The current host has previously returned IDs from the creation interface even though the primitives were not added to the document. The local candidate calls `get(id)` and `getAllPrimitiveId` segment by segment within a shared total time limit, checking ID, net, layer, coordinates, and width (explicitly requested or calculated from `currentA`) while binding to the current PCB focus. Only confirmed IDs are added to `segmentIds`. If a segment is unconfirmed, retain `failedPrimitiveId` in `cause`, return an error with `partial:true` and `retryable:false`, and stop later segments. Do not add a replacement, retry, or delete. Local regression and the corresponding expert review passed; host fix acceptance remains pending.

Automatic net names such as `$1N1` can be used directly as the `net` parameter. Other literal text beginning with `$` can be written as `$$name`; macro variables continue to use `$stepID.field`.

Temporary v0.20.38 plugin input policy: check all pending `routeTrack` segments, all SES input segments, and all planned-difference segments for length before any write. After calculating from coordinates, explicitly reject if any segment is `<1 mil (25.4 μm)`, and report its index, length, and threshold. Existing short segments are also rejected. Do not drop, lengthen, or round segments. This is plugin input policy, not an SDK minimum. The candidate passed focused local regression and final review; host acceptance remains pending.

Autorouting can be started with `autoRouteStart`, stopped with `autoRouteStop`, and, as needed, exported to DSN or supplemented manually with SES. Since v0.20.38, `autoRouteStatus` is read-only; `noImport:false` cannot trigger automatic back-import either. When a task is `COMPLETED`, the response includes `imported:false`, `autoImportEnabled:false`, and a clear explanation; it returns no `output` or snapshot, writes nothing to the PCB, does not call DRC, and does not mark `consumed`. Only the matching default task slot is released; an explicit `jobId` remains queryable, and existing write protection is not cleared. While automatic back-import is disabled, do not recommend direct back-import as the default workflow. Review and local regression passed. With EDA 4.1.78 and a local test service returning a fixed completed result, tests verified that all three `noImport` inputs request no output, write nothing to the board, and release the default task slot. This does not validate the routing algorithm.

External SES output has used multiline `wire`, `path`, and coordinate pairs. In the v0.20.30 host, five short segments still did not appear, and a long-track comparison also showed a width change; this does not establish that the format change fixed the import issue. Reconstructed wires/vias do not retain the original `type` field, so preservation of all wire metadata is not promised.

The v0.20.36 A14/A15 local candidate keeps the current parsing, mapping, planning, and difference tolerances, and selects the backend before writing: use `direct-primitives` when no new via is added or the plan already includes a trusted complete drill diameter; when a new via lacks a drill diameter, continue to use the `native-ses` entry point, without treating coverage as proof that the drill was verified. After writing begins, do not switch backends or retry. A new required `strategy` is not needed; the receipt may record the actual `backend`.

`direct-primitives` performs a fresh get on each item, checks ID membership and complete geometry, then checks the full source and geometry batch. Failures from either the `direct-primitives` or `native-ses` SES backend use a dedicated recovery hook; do not fall back to `setDocumentSource`. Roll back newly added items precisely and compare against the complete baseline only when all writes have clearly finished, all original records (including `POURED`) remain intact, and new content consists only of known candidate IDs of type LINE/VIA. For timeouts, thrown errors with unknown outcomes, unknown new items, or changes to original records, do not compensate; return partial and keep the interlock.

A15 first adds and verifies original and new primitives, then deletes old unlocked LINE/VIA/ARC items. If failure occurs after deletion of old items begins, do not recreate old IDs or restore the whole-page source. Still return partial and keep the interlock. Mark `consumed` only after final full verification passes; report DRC separately. Support for 0.04 mil short lines and atomicity of the deletion phase remain unresolved. Focused local regression and the same expert's final review passed; installed-host acceptance remains pending.

In host session `282825b0`, the first SES write in v0.20.36 failed because the runtime lacked `structuredClone`; the source and valid records, `POURED`, three LINEs, and one VIA remained intact. The v0.20.37 local candidate changes only three internal `expectedGeometry`/journal snapshot clones to local JSON deep copies. It adds no polyfill and changes neither geometry nor recovery semantics. Focused local regression and final review passed; host retest remains pending.

On failure, `cause.sesDiagnostic` includes `{ref,available,persisted,storageKey,issues,record}`. `available=true` means the inline `record` is available; `persisted=true` means extension storage was written and read back; `record.storageKeys` records storage keys before and after recovery. The record captures the command, document, UTC time, current stage, SDK call status and result, full input/UTF-8 byte count/SHA-256, target and difference geometry, and full source and line/via/arc snapshots before and after recovery. Unreadable values and reasons are recorded in `issues`. Each diagnostic stage waits at most 500 ms; on timeout, remaining reads for that stage are skipped and recovery continues. Late results do not change the record. Diagnostic failure does not block recovery or change the original error or the `partial`, `restored`, `retryable`, and `recovery` results. Successful calls do not attach a diagnostic record; they are still checked against actual geometry readback.

`autoRouteStart.maxPasses` must be a positive integer. The plugin binds an autorouting task to the PCB active at startup. After switching to another PCB, `autoRouteStatus` refuses to clear tracks or back-import; return to the original PCB and check it first. For an ended task, `autoRouteStop` returns `cancelled=false` and sends no cancellation request. After sending a cancellation request, it reports `cancelled=true` only after reading back `CANCELLED` status.

The v0.20.29 candidate strictly checks that `autoRouteStart.skipDrc` and `autoRouteStatus.noImport` are booleans; non-boolean values are rejected before EDA or service requests. Both still default to `false`. The new checks await acceptance on a newer host.

The v0.20.29 candidate allows cancellation of `QUEUED` tasks, but reports `cancelled:true` only after reading a cancelled terminal state. Calling `autoRouteStop` on a completed task returns `cancelled:false` and releases the default active task slot. Keep the returned `jobId` and pass it explicitly for later reads or back-import of that task. Unconfirmed-write recovery protection is not cleared by this. The new behavior awaits acceptance on a newer host.

Colors for `pcb.createNetClass` and `pcb.createEqualLengthGroup` accept `#RGB`, `#RGBA`, `#RRGGBB`, or `#RRGGBBAA`; the plugin converts them to the SDK's RGBA object.
`pcb.checkPlacement.minClearance` must be a non-negative finite number. Coordinates for `pcb.getPrimitiveAtPoint` and `pcb.getPrimitivesInRegion` must be finite numbers.

## Copper Pours and Silkscreen

`pcb.pourCopper` creates a boundary. Rebuild it with `rebuildPour`, then confirm the actual fill with `listPours` or `getPourFillReadback`. `pcb.listPours(withFill:true)` returns `fillStatus` as `filled`, `empty`, or `unknown`; `filledRegions` is the count of regions whose fill is true and whose path source passes basic structural checks, and `fillRegions` is the total region count. Missing or invalid readback fields produce `unknown`. In v0.20.51, the EDA 4.1.78 sample with one filled region and one unfilled region passed save/reopen verification; invalid returns and the all-`fill:false` branch were verified with local simulation. Do not report a pour complete when fill status is `empty` or `unknown`. `rebuildPour` returning `completed` does not prove the fill is fresh, saved, or manufacturing-compliant. Check fill again after changing the boundary, priority, or nearby routing. If the result is unclear, stop; do not treat an old fill as the current result.

For local copper, distinguish `pour` (clipped by rules) from `fill` (fixed fill), plan with [Geometry Commands](commands-pcb-special.md), then execute. An arbitrary priority value in `modifyPour` is not guaranteed to be attainable; use source readback after writing and do not assume success from the API response. In v0.20.41 host tests, a same-net no-op passed and four change-net requests were rejected before writing; the underlying order issue for actual net changes remains unfixed. Starting in v0.20.42, changes to a different net or `pourName` are temporarily disabled: the current value must be confirmed consistently by source and a fresh getter. If a request changes the net or name, reject the entire request before writing, including mixed requests. Same-net/same-name fields are not written; other allowed properties in the same request continue under the existing rules and are read back; unrequested properties retain their values. `layer`, `width`, and `priority` are not disabled. `toAsync` is not required, and AI is not advised to automatically delete and recreate a pour as a lossless substitute. Focused local regression and the EDA 4.1.78 tests for pre-write rejection of net/name changes, skipping same values, and save/reopen of an allowed priority change passed for the specified samples. The underlying net/name change ordering issue remains unfixed.

`pourCopper` can optionally use `net` to specify the net for a new copper pour. `preserveSilos` accepts only a boolean; when omitted, the SDK default is preserved. The command only creates a copper boundary; it does not rebuild or fill it automatically. Manual creation or modification in the EDA UI remains available, but verify the ordering, rebuild, and read back the actual fill. If readback differs, report a partial result and retain the created boundary ID; do not retry or delete it before inspecting the live board. Do not describe deleting an old boundary and creating a new one as a lossless net/name change. A single live sample with `preserveSilos:true` had matching three-way inputs and read four fills, but the POURED/save-reopen/connection checks did not pass, so this cannot be reported as successful. See [Changelog](../CHANGELOG.md).

The v0.20.40 `pourCopper` path candidate accepts only a single R path in one dimension or with exactly one wrapper layer, and strictly checks equality of all seven items. Multiple rings, additional nesting, or changed parameters should be rejected. Detailed diagnostics show raw and normalized input. Focused candidate checks passed locally; unified regression and a newer-host test remain pending.

After `placeString` or `modifyString`, check readability, mirroring, orientation, pad obstruction, and board-edge clearance. Net silkscreen must also use the planning command and be checked on the actual board view.

## Checks, Saving, and Manufacturing Exports

After routing and copper pours, run `pcb.runDrc`; use `runDrcDetailed` to locate specific issues. If either command returns a non-array result, it reports “result cannot be determined”; do not treat that as zero items or a pass. DRC does not cover component bodies, all mechanical constraints, or manufacturing requirements. See [Order Checks](commands-pcb-special.md) for materials, units, and coverage of `runDfm`, `runSmtDfm`, and same-net pad spacing. Do not report a pass when checks do not cover the full scope.

After saving at each stage, check target and non-target objects. To establish persistence, close, reopen, and read back again. After exporting Gerber, pick-and-place coordinates, or a netlist, also check which PCB version the file represents, its format, units, and actual contents. See [Networks and Exports](commands-pcb-special.md).

`pcb.exportPickPlace` supports only `xlsx` or `csv` for `fileType`, defaulting to `csv`; `unit` supports only `mm` or `mil`, defaulting to `mm`. After export, check the coordinates and units in the file; a successful return alone is insufficient.

Before deletion, inspect the target primitive IDs and make a backup. File backups in the proxy retain the five most recent backups per project, with the limit shared by all PCBs. If the proxy is unavailable, it falls back to one fixed key in extension storage shared across projects and PCBs; each new backup overwrites the previous one, retaining only the most recent backup. `pcb.delete` rejects an empty ID list or blank IDs before starting a task. If readback is unknown, stop further deletion. Use `pcb.sourceRollback` only when restoration from a backup is confirmed as necessary. Check the PCB UUID before restoring, then read back and save after restoration. Closing a tab is not a reliable rollback.

After a destructive operation fails, the plugin checks the current focus, document UUID, document type, and full source within 500 ms. Only when it confirms that the original content has not changed does it skip `setDocumentSource`, while still reporting the operation failure. `cause` is marked with `restored:true`, `contentRestored:true`, `noRecoveryWriteNeeded:true`, and `retryable:true`, and preserves `operationError`, `recovery`, and `normalizations`. If the check times out or the result is uncertain, continue the original full-source recovery flow. Source comparison still includes `POURED`. This is a local candidate; host acceptance remains pending.
