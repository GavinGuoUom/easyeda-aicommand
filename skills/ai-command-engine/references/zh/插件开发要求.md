# 插件开发要求

仅在开发、修改或审查插件指令时读取。

开发、修改和审查插件指令时，必须先遵守本节，再执行后文流程。

- 先实现功能并跑通正常使用流程，再审查安全性和限制是否必要。
- 不得让额外限制或开发检查阻挡功能实现。
- 指令必须完成它承诺的操作，并由插件自己检查结果。
- 不得把开发记录、测试步骤和验收过程变成普通使用的前置条件。
- 不得因开发方便、历史问题或宿主行为差异增加无用限制。
- 遇到宿主行为差异，必须完善插件适配，不能靠增加限制代替修复。
- 可由插件完成的检查，必须在插件内完成，不得转嫁给使用者。
- 只保留防止改错工程、错误连接、重复写入和明确运行错误的必要检查。
- 新增限制必须说明它防止的具体错误，并优先通过插件内部处理解决。
- 结果能确认时，必须明确返回成功或失败，不得一律返回待验证。
- 结果确实无法确认时，必须说明原因并停止依赖该结果的操作，不得自动重试未知写入。
- 交付前必须检查正常使用流程能够完成，不能只以代码编译通过作为完成依据。

## 插件内部源码记录处理

仅用于插件内部实现。
普通绘图不直接写文档源码。

- 文档源码是**行式 JSON 变更日志**（`JSON(header)||JSON(data)`，同 (type,id) 由 ticket 分新旧，空 data=删除墓碑），不是快照。
- 安全写法：**append-only**——① 不编辑旧行，变更追加文末。
- ② ticket 从 max+1 单调递增。
- ③ 改图元用原 data 浅拷贝只覆盖要改的键。
- ④ 移动器件坐标双字段同改（x/y/angle 与 positionX/positionY/rotation 一起）。
- ⑤ 删除用墓碑不物理删行。
- ⑥ 写入前整份备份、写后回读逐值比对（容差 0.001）、失败整份恢复、全过才 save。
- 生成图元一律 `spg_` 前缀+文档层 layerId=13 便于清场。
- 管线封装在 `pcb.groupBySchematicRegions`/`pcb.sourceRollback`（基础设施 `src/pcb/sourcelog.ts`）。
