# Extension Development Requirements

Read this page only when developing, changing, or reviewing extension commands.

Follow these requirements before using the workflow below.

- Implement the feature and make the normal user workflow work first. Then review whether each safety restriction is necessary.
- Do not let extra restrictions or development checks block feature implementation.
- A command must complete the operation it promises and check its own result inside the extension.
- Do not make development notes, test steps, or acceptance procedures prerequisites for ordinary use.
- Do not add unnecessary restrictions for developer convenience, historical problems, or host differences.
- When host behavior differs, adapt the extension; do not use new restrictions as a substitute for a fix.
- Checks the extension can perform must be implemented inside it rather than delegated to users.
- Keep only checks needed to prevent changes to the wrong project, incorrect connections, duplicate writes, or clear runtime errors.
- Explain the specific error prevented by every new restriction. Prefer handling it inside the extension.
- When the result is known, report success or failure clearly; do not return “pending verification” for every outcome.
- When the result truly cannot be confirmed, explain why and stop operations that depend on it. Do not automatically retry a write with an unknown outcome.
- Before delivery, verify that the normal user workflow can complete. A successful compile alone is not sufficient.
